# MotionCam APK audit and recording geometry changes

The user supplied `MotionCam_Pro-v5.0.8-pro-Dooms_Morphe_Patches-v1.23.1-dev.1.apk` (package `com.motioncam.pro`, version code 3308). Static Android resource inspection shows UI entries for RAW video, Direct Log preview, custom and exact recording resolutions, bitrate modes, installed/imported LUTs, histogram and extended/RAW histogram, focus peaking sensitivities and focus tween, audio presets/input/meter, stabilization, and video recovery. Resource names establish an exposed control; they do **not** establish that a feature works on every device or reveal its implementation. No third-party bytecode, native library, assets, or profile data were copied.

The current PhotonCamera source already contains encoded Log profiles with monitor/baked LUT choice, manual exposure/focus controls, preview histogram/zebra/false colour/focus peaking, audio input selection and cleanup controls, stabilization choices, resolution/FPS/codec/bitrate controls, recording diagnostics, and gallery grading tools. Existing `docs/video-174-handoff.md` details the limitations of these features.

This change fixes a concrete raster mismatch: lower-resolution and open-gate output sizes were expressed in portrait axes even though Camera2 supplies a landscape-axis SurfaceTexture. A landscape camera frame was cropped against a portrait encoder canvas and then rotated by MP4 metadata, causing severe squeeze/cropping. Encoder output now remains in camera-buffer axes at every resolution; the MP4 rotation hint for the ordinary SurfaceTexture path incorporates Camera2 sensor orientation, device orientation and lens facing. Enhanced stabilization uses a separate sensor-rotated YUV path, so it retains its device-only hint pending physical-device verification. The camera rotation is frozen when recording starts; rotating a phone during one take does not rotate an existing MP4 track midstream.

Quick-control selections already supported six reorderable slots and workspace presets. The configuration dialog now offers **Show selected buttons on viewfinder**. This opens a compact menu of those slots on the viewfinder; selection invokes the same actions as the top bar and closes the menu. It hides while recording and during advanced capture to avoid covering the subject.

The gallery Detail and noise crop now accepts a direct drag on the displayed image to reposition the source region and a pinch to inspect it more closely. The two position sliders were removed; the remaining sliders control detail processing only.

The 2× finish upscale policy no longer rejects a bitmap solely because HDR/gainmap is enabled. The bitmap path preserves its gainmap (or the explicit export gainmap) alongside the upscaled SDR base. HDR is intentionally excluded from the streaming JPEG path because that path cannot encode a gainmap; large HDR sources beyond the bitmap/memory budget retain their original output and report the limit.

## Verification and remaining work

- Geometry/orientation tests were added, but the Android SDK and Gradle toolchain were removed by workspace maintenance during this session. The recovered source archive therefore has **not** been compiled or tested. Rebuild with `./gradlew :app:testDefaultDebugUnitTest :app:assembleDefaultDebug` in an Android SDK/JDK 21 environment before distribution.
- Record a 1080p and 4K clip in portrait, landscape left, landscape right, and front camera; inspect actual MP4 width/height/rotation, gallery playback and a second external player. Check enhanced stabilization separately. The supplied image is a screenshot, not the problematic MP4, so visual proof on the user's device is still required.
- MotionCam's continuous Bayer RAW video/MCRAW format, RAW-derived DirectLog, RAW histogram and clipping, focus tween, audio meter, recovery and custom resolutions were **not** added in this change. They require separate architecture, capability and sustained-write testing; MotionCam proprietary format compatibility is not implied.
- 10-bit HDR video, temporal video denoising, and other previously discussed advanced video processing remain outstanding unless the repo implements them independently and they are validated on-device. Do not label SDR custom Log as HDR10/HLG or encoded video as RAW.

Recording integrity follow-up: a MediaMuxer sample-write exception now invalidates the session and prevents publication, even if stop succeeds. This prevents exposing known-incomplete output; it is not a verified fix for the screenshot duration issue. Android compilation remains blocked by the missing toolchain.
