## Candidate UI, not fully verified implementation

- Horizon Steady: help describes sensor-driven saved-video leveling within ±20°, cropped edges, unstabilized viewfinder, unavailable on direct native 10-bit HDR. Resources `strings.xml:1774–1778`, UI title/toggle references in `r77.smali:33027,33166,34113` and callback metadata `j90.smali:1120–1128` establish a reachable control. This inspection did **not** close the chain from that setting through timed sensor samples to encoded-frame transform. Do not list it as verified functioning stabilization. Current source already has substantial EIS (`stabilization/RealtimeStabilizationCoordinator.kt`, MgcEisNativeEngine), so first evaluate whether horizon leveling fits that coordinator.
- Offline shooting assistant and scene recipes: strings `:55–65,155–162,1169 onward` and title ID references `cy0.smali:1139`, `g60.smali:452` prove UI content. They describe local exposure/focus/face-based advice, not generative AI. This inspection did not prove each suggestion's telemetry predicates or each scene's complete camera-setting application. Treat as a UX/rule-engine idea, not verified computational scene recognition.

## Existing features should not be counted again

The authoritative source already includes processed Log video and selectable profiles, LUT monitor/bake behavior, HDR bracket fusion, manual controls, RAW/RAWmax, advanced EIS and focus-bracket logic. Current resource text is newer in places than the APK (for example explicit focus-bracket settling/save semantics). A name, icon, shader asset, translation, decoder class or manifest declaration alone does not prove a new usable feature. Binary differences alone do not establish improvement. The APK's additional broad UI catalog should not be used as a port checklist without source and execution comparisons.
